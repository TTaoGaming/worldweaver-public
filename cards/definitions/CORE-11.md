## Use this card
Status: EDITORIAL_PROPOSAL_NOT_EXECUTED

Candidate behavior: assemble the smallest compatible capability set that can produce the requested result.

When: When equipping a worker or checking whether an existing composition fits a new task.

### Inputs
- WorkItem inputs, required outputs and effect ceiling
- Versioned equipment/interface references, carrier requirements and budget

### Procedure
- Map each task requirement to a needed capability.
- Select attachments with explicit revisions and identify their dependencies.
- Check interface compatibility and distinguish capability availability from permission to use it.
- Produce a composition proposal and bounded verification plan; name unresolved bindings.

### Outputs
- Requirement-to-equipment mapping
- Versioned loadout proposal with compatibility evidence and gaps

### Failure modes
- Accumulating tools without a task need
- Treating a model as the durable actor
- Assuming installed equipment grants effect authority

### Worked example
- situation: A worker must summarize supplied documents and produce a cited table.
- action: Select only compatible reading and table-output capabilities; explain every attachment's purpose.
- evidence: Expected: interface references, output contract and a relevant bounded verification plan.

### Neurosymbolic division of work
- neural: Reason about task needs and alternative compositions.
- symbolic: Bind interfaces, revisions, dependencies, effects and budget.

### Evolution contract
Mutable: Attachment selection within authorized compatible options
Frozen: Task output contract and effect ceiling; Comparison conditions and judge
Fitness: Evaluate task correctness, compatibility failures and resource use against the same requirement set; more equipment earns no automatic credit.
